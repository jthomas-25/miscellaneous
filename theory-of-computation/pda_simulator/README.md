# PDA Simulator
Constructs a pushdown automaton (PDA) from a context-free grammar (CFG)
and then runs it on a given string.

### CFG file format
A CFG file simply lists the production rules for the grammar.
- Production rules use a notation similar to Backus-Naur form. For example,  
  here are some rules for a non-terminal symbol _S_, separated by vertical  
  bars: `S: a S a | b S b | c S c | a | b | c | _EMPTY_`
- `_EMPTY_` represents the empty string. Applying this rule removes the
  nonterminal symbol from a string.
- The start symbol is the first non-terminal in the list.

Symbols are allowed to have multiple characters. For example, consider the
following grammar that generates all valid statements in the language C\-\-:
```
STMT: VAR = VAR ; | VAR = LIT ; | if ( COND ) { BODY } ELSE
VAR: x | y
LIT: 0 | 1
COND: VAR OP VAR | VAR OP LIT | LIT OP LIT
OP: == | != | >
BODY: STMT BODY | _EMPTY_
ELSE: else { BODY } | _EMPTY_
```
This grammar is available as `examples/cminusminus.cfg`.

### Command line
Run with:
```
python3 simulator.py cfgfilename.cfg inputstring [timeout]
```
The symbols in the input string do not have to be separated by whitespace.

A string is well-formed if all of its symbols are terminals. A
malformed string will cause the following error message to appear:
```
Malformed string: unexpected symbol {symbol}.
```
The simulator's default behavior is to run until it either accepts or  
rejects the string. To prevent excessive/infinite looping, hold `Ctrl+C`  
or pass the `timeout` argument, which is the minimum number of seconds to  
compute before stopping. The time-out interval must be positive.

### Performance
This program is experimental and simulates a _nondeterministic PDA_. Different  
runs can produce different results for the same input. If a string is known to  
be in the language generated by a CFG, the automaton may accept it correctly  
on one run and reject it incorrectly on other runs. However, if the string is  
not in the language, the automaton will never accept it.

Specific properties of the grammar, such as whether it is ambiguous or LL(1),  
can greatly affect the automaton's performance. The length of the input  
string is also a factor in execution time.

### Remarks on nondeterminism
Nondeterminism occurs when a CFG contains several production rules for a  
non-terminal symbol; the equivalent automaton thus has several transitions it  
may take when a non-terminal symbol appears at the top of the stack. By  
contrast, a _deterministic PDA_ (DPDA), has at most one transition it can  
follow during each step of its computation. As a result, DPDAs use far fewer  
resources than nondeterministic ones.

The simulator reads an arbitrary CFG, so it can recognize any context-free  
language. It does not use LL(1) or LR(1) parsing, since these algorithms are  
implemented by DPDAs. DPDAs only recognize deterministic context-free  
languages. Some languages are not deterministic context-free, like the language  
of all palindromes over the alphabet {a,b,c}. This means that nondeterminism  
makes PDAs more powerful, but less efficient at parsing.
